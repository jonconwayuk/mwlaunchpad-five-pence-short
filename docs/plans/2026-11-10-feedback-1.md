## Global Constraints (paste into every brief, both workstreams)

> - Invoke `ponytail:ponytail` first, and work to it: the smallest complete change, low token use, no re-reading files you just wrote.
> - **You own only the files your brief lists.** If you need a change elsewhere, leave a `// NEEDS: <what and why>` comment in a file you own and report it. Do not run `git add` or `git commit`; report your files and the orchestrator commits them.
> - **Additive only.**
>   - Do not rename routes. `/portal` stays; only the visible name changes.
>   - Do not change existing API response shapes.
>   - Do not change the meaning of any field in `src/engine/types.ts`. New fields are optional.
>   - The integer `version` that Applied Pathways pin (ADR-0001 and ADR-0002) stays. Semantic versioning is layered on top.
> - The test count never drops. Reset demo still restores the seeded state. `BUILD-PLAN.md` section 9 still passes for the existing personas.
> - **Stack and standards:**
>   - The stack is in `BUILD-PLAN.md` section 2. Add no new runtime dependency without a recorded decision. No second git repo. No Azure or Microsoft 365 resources.
>   - TypeScript strict. No `any`, no `console.log`. `new Date()` appears only in `src/lib/clock.ts` and `src/db/seed.ts`.
>   - Validate with zod at every boundary, and send errors through `apiHandler`/`ApiError`.
>   - Synthetic data only. No secrets. No local paths in evidence: write `<repo>`.
> - **Words:**
>   - Use `GLOSSARY.md` vocabulary and none of its Avoid words.
>   - The visible name of `/portal` is **Onboarding Studio**.
>   - Item 14 is **"Send a Reminder now"**.
> - **Screens other than the Journey builder:**
>   - plain words and one primary button per screen;
>   - no jargon and no dense tables;
>   - usable with no training.
> - **UI tasks:**
>   - Use `taste-skill:design-taste-frontend` and `engineering-skills:senior-frontend` (`frontend-design` is not installed; decision 13).
>   - Use `dataviz` on charts.
>   - Use the existing tokens only, with no new colours, and keep to `BUILD-PLAN.md` section 5.
> - **Running and checking:**
>   - Use your own database: `DATABASE_URL=file:/tmp/<task>.db npm run seed`.
>   - Use your own dev server: `NEXT_DIST_DIR=.next-<task> npx next dev -p <your port>`. Never use port 3000; the team's demo runs there.
>   - Kill the server and delete its directory and database when you finish, then run `git checkout tsconfig.json` (CLAUDE.md Traps).
>   - Run tsc, eslint and vitest scoped to your own paths, and never fix files you do not own.
> - **Ambiguity:** never ask the owner. Take the fallback, report it, and carry on. If an item cannot be done without breaking section 9, changing a contract or redoing finished work, park it with one paragraph and carry on.
> - **Closing message:** short. Each Done-when line with its evidence and whether it was run or only reviewed, your files, any NEEDS notes, and any decisions taken.
